## First comment

Hi HN, I'm [name], [one line on who you are: e.g. electrical engineer / developer at …].

OpenECraft is an electrical CAE tool: the software used to design the control
cabinets of machines and plants. You draw the schematic, but the program thinks in
devices: a contactor -K1 is one device whose coil and contacts sit on different pages,
with live cross references between them. From the schematic it generates the bill of
materials, terminal and cable diagrams, connection lists and PLC tag tables, and it lays
the devices out in the cabinet in 3D with the wires routed through the cable ducts.
The commercial standard for this in Europe is EPLAN, which is Windows-only and
commercially licensed; I wanted something open that runs anywhere.

Try it without installing: https://editor.openecraft.org (File › New › Example
projects; "3 · Star-delta motor starter" is a good start, "4 · Conveyor" has the
panel in 3D). The website https://openecraft.org has smaller live demos. Desktop
installers for Windows, macOS and Linux are on the GitHub releases page.

Some technical details:

- Rust, one workspace of 24 crates. A headless core (about 120k lines) holds the
  project model, netlist, checks, reports, 3D layout and the SVG / PDF / DXF / DWG
  exports; the editor is egui/eframe on the desktop and as WebAssembly in the browser.
- Canvas, SVG, PDF and DXF all draw through one `Draw` trait, so the PDF that goes to
  the customer matches the screen.
- Every function on the project (about 300 commands) is an entry in a plugin
  registry, which the editor, the command line and an MCP server for AI agents all
  read from.
- The browser build was 61 MB of WebAssembly; leaving 16 language catalogs out (fetched
  on demand), an opt-level "s" + fat LTO profile and pre-compression got it to 32 MB,
  8 MB with Brotli. Still big; the page shows a progress bar.
- Expensive 3D cable routing runs in a web worker that hosts a second instance of the
  same module.

Being upfront about how it was built: the project is one month old (first commit
2026-10-19), and most of the code was written with AI coding agents (Claude Code) –
338 of 468 commits carry the co-author trailer. [Your own words: what you did –
specification, domain knowledge, review, testing.] The guardrails are tests: layer
rules for the core crate, every UI text in the catalog with four required languages,
every string checked against the bundled fonts, 16 example projects that must pass the
project check with no warnings, about 2,800 tests in all.

What is solid: schematics, devices, terminals, cables, reports, project check, PDF/DXF
export, PLC tag export. What is young: 3D routing in rooms and buildings, floor plan
scans, STEP/IGES import, the collaboration server. There is no import of EPLAN
projects (only EDZ parts/macros). The bundled manufacturer catalogs are compiled from
data sheets – check before ordering.

I'd especially like to hear from people who design control panels: what would stop you
from using this for a real job? Bug reports are welcome on GitHub (the editor has a
*Report a bug* button that fills in an issue form; nothing is sent automatically).

Code: https://github.com/nilres/OpenECraft – MIT or Apache-2.0.
